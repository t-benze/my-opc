# Managed remote access: Linux package operations (N3)

Under THR-097 seq566, packaged-sidecar startup diagnosis is limited to four redacted classes: `credential_input`, `engine_start`, `network_join`, and `durable_commit`. Evidence binds the mapped phase, actor/unit, failed terminal outcome, and completed assertion, and rejects missing, duplicate, prose-only, unmapped, inconsistent, incomplete, or secret-bearing receipts. This reports the observed current seam; the credential-delivery redesign remains future work.

Both separate services retain `NotifyAccess=main`. Systemd starts them concurrently, without a connector/sidecar readiness-ordering cycle. The connector Go MainPID starts the frozen Python child with a private health pipe and without `NOTIFY_SOCKET`; canonical versioned, generation-bound, strictly monotonic records are necessary but not sufficient for READY/WATCHDOG: the sidecar unit must also be active, which means its enrollment, ExpectedPeers, listener, and connector-reachability gates completed. A single monotonic startup deadline is never refreshed by waiting or partial progress. After READY, only a complete current connector-plus-sidecar health observation refreshes liveness. Missing/stale, malformed, partial, duplicated, reordered, unknown, exited-service, or lost composite health stops watchdog publication and fails closed.

N3 composes the portable Python connector and embedded Linux tsnet sidecar into one reproducible root-owned artifact. In system-service mode its payload root, binary directory, and binaries are mode `0755`, so dedicated non-root system-service users can traverse to and execute the binaries while ownership remains root. The installer selects that contract only with explicit `system_service=True`; optional no-root installation keeps those directories and binaries owner-only (`0700`). It does not provision a control plane, deploy a service, enable managed access by default, or begin macOS work.

```sh
cd app/linux/tsnet-sidecar
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -buildvcs=false -o ../../../dist/happyranch-tsnet-sidecar ./cmd/happyranch-tsnet-sidecar
python tools/generate_inventory.py
cd ../../..
uv build --wheel --out-dir dist
uv run python app/linux/package/build_connector.py --wheel dist/happyranch-0.1.0-py3-none-any.whl --output dist/happyranch-connector
uv run python app/linux/package/build_package.py --sidecar dist/happyranch-tsnet-sidecar --connector dist/happyranch-connector --wheel dist/happyranch-0.1.0-py3-none-any.whl --version 0.1.0 --output dist/happyranch-linux-amd64.tar
```

The manifest hashes every payload. `share/sbom.cdx.json` and `share/THIRD_PARTY_NOTICES.md` couple to the exact checksum-pinned N1 inventory; composition refuses a module missing from the notices. No dependency resolution occurs during composition.

`build_connector.py` installs the real wheel into an isolated build target and freezes that installed code with the repository-pinned PyInstaller build dependency. The archive therefore carries an explicit self-contained Python executable; it never relies on a source checkout, ambient `python`, or an inert wheel as launch proof. The wheel remains bundled as an exact receipt.

Before publication, the shared credential-capability preflight classifies each unit's root-custodied `0600` source as absent, wrong type, unsafe symlink, wrong custody, staging-incompatible, or valid using category-only output. At start, each unit requires the exact `/run/credentials/<unit>` provenance and exact basename and invokes the same preflight against only its own systemd-staged copy: the connector checks `daemon.token`; the sidecar checks `enrollment.key` and never receives the daemon bearer. Staged validation is ownership-neutral because systemd determines staged ownership; it accepts only a regular, non-symlink credential that the service can read but cannot open for writing. First enrollment comes exclusively from `$CREDENTIALS_DIRECTORY/enrollment.key`, staged by a transient owner-only systemd drop-in; staged files are never copied or unlinked by service users, and `StateDirectoryMode=0700` is explicit. Only after READY and durable consumption does the elevated helper remove and reload the drop-in before retiring the source; its privileged preflight finishes an interrupted source unlink. Ordinary, crash, and stopped-service restarts therefore use durable state without requesting the retired credential, while a missing marker fails closed. Fresh re-enrollment requires an explicit stopped-service operator action: install a new root-owned `0600` source, invoke `prepare-fresh-enrollment` to replace consumed state and publish/reload the transient drop-in, then start the composite. Each MainPID owns only its unit READY/WATCHDOG. Connector watchdog refresh additionally requires a bounded-fresh complete systemd state for both units; stale, stopped, failed, restarting, unknown, timed-out, malformed, or missing-service observations cease composite health. Removal is tri-state: only confirmed absence permits downstream cleanup, confirmed presence triggers bounded stop/re-observation, and unknown fails closed. Target stop removes sidecar admission before connector cleanup.

The dedicated `Managed N3 Real systemd (Ubuntu 24.04)` CI job is fail-closed and zero-skip. It qualifies PID 1, the system manager, passwordless sudo, and transient units; verifies native Headscale v0.25.1 sha256 `d2cda0a5d748587f77c920a76cd1bf1ab429e5299ba5bc6b3dda90712721b45b` and the reused CI-only Tailscale 1.102.3 peer tarball sha256 `36ddd9b51be57ffc2990cf76323cfa13643bfbb1b8a969f6183fa164741cdef5`; then requires the packaged production tsnet sidecar to see `synthetic-peer-ci` through `ExpectedPeers` before systemd READY. Both artifacts are BSD-3-Clause and already covered by the existing CI-lab artifact policy; this unit introduces no new distributed package input or notices duty. The genuine peer probes the virtual TSNet `:443` listener directly; host port 443 and connector port 18443 are not admission evidence. Explicit systemd barriers force both orderings. The packaged process calls production `Sidecar.Stop` twice on the same instance and emits PID/invocation-scoped receipts. Every fresh publication fault proves payload, units, markers, backups, stages, and temporary parents absent before successful same-root re-entry; upgrade rollback/re-entry remains required. Cleanup probes virtual admission gone while the peer is alive, then reaps all processes and proves all listeners, MainPIDs, units, package/config/state/runtime/log paths and transaction residue absent. Diagnostics live outside the cleaned work root. Only a successful run finalizes the versioned execution artifact; it binds exact git head, package digest, unique run, unique phase/observation records, completed assertions, zero skips/fakes, terminal completeness, and a whole-document digest. CI independently validates and always uploads it and diagnostics. N3 does not exercise or claim admitted HappyRanch requests or authorization-negative behavior; those proofs remain N6.

The installer validates duplicate-free exact archive/manifest membership against a closed path set, normalized paths, strict non-boolean schemas, architecture, count, hashes, and modes before any write. Inventory and CycloneDX fields (coordinate, purl, SPDX, go.sum and license checksum) plus structured notice coordinates/SPDX/checksum/content match one-to-one. A durable owner-only transaction marker classifies publication state. On re-entry it either restores the last-known-good payload and units and removes staging residue before a fresh install, or rejects an incoherent marker/backup composition; it never silently deletes an unexplained backup.

The acceptance-only AF_NETLINK diagnostic runs four fresh-reset arms in the fixed order A-control, A-candidate, B-candidate, B-control. Every arm uses the same exact package and pinned non-secret inputs plus a fresh fixture-only one-use enrollment credential. Controls use the shipping unit and require exactly one coarse `engine_start/engine_initialization` receipt after the arm-start journal cursor and bound to the current systemd invocation. Candidates add only a transient harness-created `AF_NETLINK` drop-in and must independently prove composite READY, an arm-fresh production consumption marker committed after `TSNetEngine` sees its sole configured expected peer, and genuine virtual TSNet listener reachability from the peer. Candidate state is cleared before acquiring a fresh pre-reset cursor. Every candidate failure executes all five bounded denial probes, settles and pins the current invocation, and preserves a strict snapshot before destructive teardown containing only the exact arm and fixed phase, approved coarse category sets and exact pinned/window counts, zero/one/multiple cardinality, and Result/ExecMainStatus. Cleanup and post-cleanup failures reuse that validated snapshot; they never query a removed unit. If a current envelope cannot be established, the harness fails closed, performs exhaustive cleanup, and retains only a validated fixed-code preservation-failure record. Raw journals and prose never survive. Cleanup removes the drop-in and all unit, fixture, credential, process, listener, package, configuration, state, log, transaction, backup, stage, and temporary-parent residue on every exit without deleting diagnostics. The validator rejects arm/order/identity drift, skips/fakes, partial gates, incomplete cleanup, ordering bias, fine-grained control reasons, unmeasured/default denial matrices, missing or tampered candidate terminal evidence, non-assertion substitutes, tampering, and secrets. A green A/B establishes only an exact-environment proximate variable; it grants no production correction authority.

Install/upgrade/uninstall functions take an explicit fixture root and validate the manifest before mutation, enabling tests without touching the host. Production installation, service enablement, deployment, signing, and launch remain gated.
